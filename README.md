# babushka-photo-printer

Telegram-бот, который следит за приватной семейной группой и автоматически печатает
присланные туда фото на принтере — без участия человека.

## Как это работает

1. Семья кидает фото в приватную Telegram-группу (обычным "Фото" или как "Файл" для
   оригинального качества без сжатия Telegram).
2. Бот (long polling, `aiogram`) ловит новое сообщение с фото/файлом-изображением.
3. Скачивает файл в максимальном доступном качестве.
4. Нормализует его перед печатью (`image_processing.py`): авто-поворот по EXIF,
   конвертация в RGB, ресайз под печать, пересохранение как чистый baseline JPEG —
   это защита от того, что generic/driverless-конвертер CUPS иногда не может
   прочитать "сырые" файлы с телефона (прогрессивный JPEG, нестандартный ICC-профиль
   и т.п.).
5. Кладёт файл во внутреннюю очередь печати (`asyncio.Queue` в `bot.py`) — фото
   печатаются строго по одному, даже если прислали сразу пачку. Фоновый воркер
   дожидается реального подтверждения от CUPS, что задание физически покинуло
   очередь принтера (а не просто было принято `lp`), прежде чем считать печать
   успешной — это защита именно от того сценария, когда CUPS принял задание,
   а принтер потом аппаратно его отклонил.
6. После подтверждённой печати запись остаётся в SQLite (кто прислал, когда,
   статус), а сам файл удаляется с диска — фото не хранятся на карте памяти
   дольше, чем нужно для печати.
7. Если печать не удалась (или принтер её отменил, или не дождались завершения
   за отведённое время) — файл не удаляется, чтобы можно было повторить.
8. На каждое фото бот отвечает в группе статусом ("✅ Фото распечатано" /
   "⚠️ Не удалось напечатать") — ответ приходит только после реального
   завершения печати, то есть может быть с задержкой в очереди, если фото
   прислали несколько подряд.

## Структура проекта

```
bot.py                    точка входа: хендлеры Telegram, оркестрация пайплайна
dashboard.py              веб-панель на Streamlit: БД, статус бота/принтера, повтор печати
config.py                 все настройки — читаются из .env
db.py                     SQLite: учёт фото и дедуп по file_unique_id
image_processing.py       нормализация фото перед печатью (Pillow)
printers/
  base.py                 абстрактный интерфейс Printer.print_photo()
  stub_printer.py         заглушка для разработки без принтера — только логирует
  cups_printer.py         печать через системную очередь CUPS (`lp`)
  __init__.py             фабрика get_printer() — выбирает backend по конфигу
```

Принтер подключён через абстракцию `Printer`, поэтому смена физического принтера
обычно сводится к правке `.env` (`PRINTER_NAME`/`PRINTER_OPTIONS`), а смена целого
подхода к печати (например, добавить Windows-бэкенд без CUPS) — это новый класс в
`printers/`, без изменений в `bot.py`.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather) |
| `GROUP_CHAT_ID` | ID приватной группы (см. ниже, как узнать) |
| `DOWNLOAD_DIR` | Куда временно класть фото перед печатью (по умолчанию `photos/incoming`) |
| `DB_PATH` | Путь к SQLite-базе (по умолчанию `data/bot.db`) |
| `PRINTER_BACKEND` | `stub` (заглушка, без реальной печати) или `cups` (реальная печать) |
| `PRINTER_NAME` | Имя очереди в CUPS, см. `lpstat -p` (только при `cups`) |
| `PRINTER_OPTIONS` | Доп. опции `lp -o ...` через запятую, см. `lpoptions -l -p <имя>` |
| `PRINT_MAX_DIMENSION` | Максимальный размер по большей стороне перед печатью, px (по умолчанию 1800) |

### Настройка бота и группы

1. Создай бота через `@BotFather` → `/newbot`.
2. В `@BotFather`: `/mybots` → бот → *Bot Settings* → *Group Privacy* → **Turn off**
   (иначе бот не увидит фото от других участников группы, только команды). Либо
   сделай бота админом группы — это тоже снимает privacy mode.
3. Создай приватную группу, добавь туда бота.
4. Узнай `GROUP_CHAT_ID`: убедись, что `bot.py` сейчас не запущен (иначе он "съест"
   апдейт через long polling), отправь любое сообщение в группу, затем:
   ```bash
   curl "https://api.telegram.org/bot<BOT_TOKEN>/getUpdates"
   ```
   В ответе найди `"chat":{"id": -100..., "title": "...", "type": "supergroup"}`.

### Настройка принтера (CUPS)

1. Добавь принтер в систему обычным способом (System Settings → Printers, или
   `lpadmin`).
2. Узнай его имя: `lpstat -p`.
3. Узнай доступные опции печати: `lpoptions -l -p <PRINTER_NAME>` — оттуда бери
   значения вроде `media=Postcard` для `PRINTER_OPTIONS`.
4. Проверь вручную перед подключением бота:
   ```bash
   lp -d <PRINTER_NAME> -o media=Postcard какое-то-фото.jpg
   ```

```bash
source .venv/bin/activate

```

## Панель мониторинга (dashboard.py)

Небольшой веб-UI на Streamlit — читает ту же БД и статус принтера, работать бот
при этом не обязан (кроме статуса "бот подключён", который зависит от heartbeat).

```bash
source .venv/bin/activate
streamlit run dashboard.py
```

Откроется на `http://localhost:8501`. Что там есть:

- **Статус бота** — читает `data/bot_heartbeat.txt`, который `bot.py` обновляет
  каждые 30 сек; если отклика нет дольше 90 сек — считает бота не запущенным.
- **Статус принтера** — не просто `lpstat -p` (он показывает только последний
  известный статус очереди CUPS и не замечает, что устройство физически
  отключили, пока не попробует напечатать), а активная проверка через `lpinfo -v`
  (реальное обнаружение по USB/сети прямо сейчас) + длина очереди CUPS. Из-за
  этого карточка статуса принтера грузится не мгновенно — `lpinfo -v` реально
  опрашивает сеть и занимает ~15-20 секунд, это нормально.
- **Метрики**: всего фото, напечатано, ожидают/не удалось, за сегодня.
- **График** — фото по дням за последние 14 дней.
- **Топ отправителей** — кто прислал больше фото.
- **Повторная печать одним кликом** — для всех фото со статусом не `printed`,
  чей файл ещё не удалён с диска (звонит в принтер напрямую, без запуска бота).
- **Таблица всей БД** с фильтрами по статусу и отправителю.
- Чекбокс автообновления страницы каждые 15 сек.

## Известные ограничения

- На альбом из нескольких фото бот отвечает на каждое отдельно (не единым
  сообщением на весь альбом).
- Подтверждение завершения печати (`CupsPrinter._wait_for_completion`) опирается на
  парсинг текстового вывода `lpstat` (проверяет, пропало ли задание из очереди, и
  не появилось ли слово "cancel" в статусе принтера) — это эвристика, а не honest
  чтение IPP job-state через API. Для наших целей достаточно, но не железобетонно.
- Официальный macOS-инсталлятор Gutenprint не ставится на macOS новее Catalina —
  на новых Mac нормальный драйвер для Selphy недоступен, только generic-путь (там и
  встречались ложные аппаратные отказы печати, из-за которых появилась логика выше).
  На Linux (Raspberry Pi и т.п.) эта проблема не актуальна — там Gutenprint ставится
  через `apt install printer-driver-gutenprint`.
